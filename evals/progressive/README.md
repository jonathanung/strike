# Progressive tool disclosure evaluation (#992 / epic #993)

Offline comparison of **full** tool exposure (`deferTools=off`) vs
**progressive** disclosure (`deferTools=on`, the default after #988–#991).

## What it measures

| Metric | Meaning |
|---|---|
| First-turn tool count | Tools bound on the first provider request |
| First-turn schema tokens | Rough `chars/4` estimate of name+description+JSON schema |
| Toolsearch calls | Discovery round-trips (fixtures aim for zero via activation) |
| Invalid / redundant tool calls | Error settlements and repeated failures |
| Completion | Fixture success predicate (solo / plan / multi-agent) |
| Wall time | Fixture duration (ms) |

## Run

```bash
go test ./internal/eval/progressive -count=1 -v
```

Sample comparison output is also written conceptually as
`evals/progressive/sample-report.json` (regenerated by tests when desired).

The existing parameter sweep remains available for live model A/B:

```bash
strike eval sweep --benchmark swebench --matrix deferTools --dry-run --limit 2 --grader none --out /tmp/sweep-defer
```

## Rollback criterion (permanent default gate)

Progressive disclosure stays the default **unless**:

1. **Completion regression:** progressive completion rate drops by more than
   **5 absolute percentage points** vs full exposure on the fixture pack, or
2. **Latency regression:** progressive median wall time rises by more than
   **+25%** relative to full exposure.

Schema reduction below **30%** on solo first-turn is a **soft warning** (not
automatic rollback). Investigate with `deferTools=off` if either hard criterion
trips; restore progressive only after the regression is understood.

Constants: `internal/eval/progressive` (`RollbackCompletionDelta`,
`RollbackWallTimeRatio`, `MinSchemaReductionRatio`).

## Compatibility

Legacy tools (`delegate`, `task_status`, `task_read`, `task_message`,
`task_interrupt`, `wait`) stay **registered**. Under progressive defaults they
are **deferred** until `toolsearch`, direct call, history resume, or workflow
activation. Prefer the unified **`task`** API for new agent behavior.

## Preferred interface

| Prefer | Avoid (compat shims) |
|---|---|
| `task` `{prompt}` / `action=status\|wait\|cancel` | `delegate` create, `task_status`, `wait` |
| `task` advanced after toolsearch / activation | Parallel use of both surfaces in one turn |
| `toolsearch` for optional built-ins | Assuming all tools are always in `tools[]` |

See [docs/config.md](../../docs/config.md) (deferred tools, progressive `task`,
workflow activation) and [docs/usage.md](../../docs/usage.md).
